## What changed because of evidence

The run repeatedly rejected convenient explanations.

Phase 1 reached successful package/API states before the native Lit pixels were readable. That prevented mechanical success from being treated as visual acceptance.

Phase 2A then exposed a same-path provenance collision. A successful logical-path export did not prove which package supplied the object. Direct package-specific loading established the real source and changed the later implementation requirement.

## Conversation replacement did not restart the task

Planner G2 resumed from Task, Plan, Memory, Plan Note, Child Reply, Result and evidence surfaces rather than the previous chat transcript.

Worker successors likewise continued from the durable Child frontier.

The durable object was the task state in Git, not one continuously surviving AI conversation.

## External jobs did not own Worker lifetime

G20 demonstrates the separation cleanly: the Worker durably handed off while the external Build/Cook job was still running, and the machine job completed afterward. A successor could inspect the same operation instead of restarting it.

## Recovery was not perfect

The run included real Harness failures and human operational intervention.

Backup Runner capacity proved useful when the primary Runner was blocked. The first Helper behavior was still insufficient, so the recovery contract was improved during the live task. The resumed Helper completed the bounded recovery and returned control to Planner.

This is therefore not a hands-off autonomy claim.

## Why the stop matters

Phase 2B accumulated useful native runtime evidence but never crossed its final acceptance boundary. G32 response-start was not enough; no durable semantic result followed.

The user chose to stop.

That explicit incomplete state is part of the showcase, not a failure hidden from it.

## Takeaway

> **One sufficiently complete task can survive for hours across short-lived AI contexts, external jobs, failed experiments, revised hypotheses and role replacement while preserving a verified execution frontier outside the conversation.**

The point is not that the AI kept running for a long time. The point is that failure became input to the next bounded decision while accepted progress remained durable.
